我觉得目前最大的问题有四个。

第一，特征还偏“事后解释”而不是“事前决策”。文档自己也点出来了，现在很多特征依赖整天、整周完成后的 realized data，这适合研究，不适合直接实盘。这个问题非常关键，因为很多研究系统死就死在这里：训练时知道“今天最终波动很大”，实盘时却不可能在上午就知道。你已经意识到要把它改成 rolling vol、rolling range、intraday state 这类 causal features，这一步不是优化项，而是上线前的必做项。

第二，当前特征集偏少，表达力可能不够。现在主特征是 returnPct、absReturnPct、realizedVolPct、avgRangePct、upMinuteRatio、featureBucket。它们能描述“波动”和“方向”，但对很多交易日并不够，尤其是区分“慢趋势”“假突破”“新闻冲击后回归”“单边逼空”“高波动无趋势”这类结构时可能会显得粗。也就是说，router 可能能解释一部分周和日，但解释不了更细的 regime。

第三，规则系统很容易变复杂，最后走向隐性过拟合。文档虽然写了“不要记忆日期、不要新增只修单个样本的规则”，这很好，但从执行上看，weekly_guard + daily_router + loss_recheck 三层叠加后，很容易出现规则越来越多、每条都能解释过去，但未来泛化下降的问题。尤其是当日级 overlay 和 loss_recheck 频繁救火时，通常意味着上游候选池或周级映射还不够强。文档其实也承认了：如果大量收益依赖 loss_recheck，说明日级和周级映射还不够好。

第四，缺少交易成本、滑点、执行约束的系统性验证。文档在“未来扩展方向”里提到要引入交易成本敏感度分析，但如果这是高频短持仓体系，这个不是以后再做，而应该尽快前置。因为 RSI+MACD+ATR 的短持仓策略，对手续费、点差、滑点非常敏感。很多训练里看起来不错的策略，一旦带上真实交易摩擦，收益结构会直接变形。

我的改善建议，会按优先级排。

第一优先级：先把“报告”补成真正可评估的报告。
你现在最需要的不是继续加规则，而是给每次训练固定输出一页 summary，至少包含：
训练期 vs 未来期的 totalPnL、returnPct、maxDrawdown、profitFactor、tradeCount、positiveDays/negativeDays、负收益周数量；以及对 default、rank1、topN equal weight 的超额表现。没有这些数字，任何“这版 router 变好了”的结论都不够硬。这个也和你文档里的评分逻辑一致：未来期总收益、未来期回撤、负收益周数量、相对基准增益，应该成为核心评价面板。

第二优先级：把特征从研究型改成可执行型。
你文档里这点写得很对，建议立刻落实。比如把：

日级 realizedVolPct 改成“开盘后前 N 分钟 rolling vol”
avgRangePct 改成“到当前时点累计 range / 过去 X 天均值”
upMinuteRatio 改成“分时 directional persistence”
增加 opening impulse、trend persistence、reversal strength、gap / event shock proxy
这样 router 才能真正用于盘中切换，而不是只能做盘后归因。

第三优先级：增强候选池，而不是急着增强路由。
文档里也说了，未来期失败先看候选池够不够好，再看周级和日级规则，这个顺序是对的。我的建议是：
不要长期只围绕 RSI+MACD+ATR 一个家族微调。BTC/ETH 这种品种通常既有趋势段，也有震荡和事件驱动段，单一家族可能天然覆盖不全。可以分阶段做：
先保留当前家族作为 baseline；
再单独训练 breakout + ATR；
再单独训练 mean reversion + VWAP；
最后不是把三种策略直接混成一个大池子，而是先分别验证哪个家族在哪类 regime 更有 edge，再决定是否进入更高层的 family router。
这样比在单一家族里堆很多参数更健康。

第四优先级：减少规则数量，增强“规则证据”。
你文档已经写了每条日级规则必须回答“修哪几天、为什么错、新策略为何更合适、有没有误伤”。我建议再加一个硬门槛：
任何新规则，至少要同时满足“覆盖多个样本 + 在未来期不恶化 + 对总收益或回撤有显著贡献”，否则不入库。
也就是说，规则不是解释过去，而是要通过一个最小泛化门槛。这样能防止 router 越训越像人工拼 patch。

第五优先级：把验证升级成更严格的 walk-forward。
文档里已经提到未来可扩展到更严格的 OOS walk-forward，我建议尽快上。因为静态切分像“2024-2025 训练、2026 验证”，容易把某个市场阶段偶然当成规律。更稳的做法是：
滚动训练窗口，例如过去 3 个月 / 6 个月训练，下一周或下一个月验证；
持续记录每轮 router 的未来表现分布；
看它是“多数窗口都略优”，还是“靠极少数窗口暴赚撑起来”。
这对真实上线价值非常大。

第六优先级：加入成本敏感度和容量分析。
既然是高频短持仓，建议每次报告强制多跑几组：
无成本 / 基础手续费 / 手续费+滑点 / 极端滑点。
再看策略收益是否还成立。否则你优化出来的可能只是“理论上赚钱”的 router，而不是“能成交后还赚钱”的 router。文档已把交易成本敏感度分析列为后续扩展，我认为它应该提前。

整体结论我会这样下：

这份方法论值得继续做，框架是对的；但它现在更像“研究平台设计完成”，还不能证明“训练结果已经可靠”。
你的强项在于：

知道不能迷信 Top1
知道必须做未来期验证
知道最终是 policy system，不是单策略
知道研究型特征和实盘型特征有区别
这些都说明方向成熟。

你当前最该补的，不是再写更多原则，而是补三样东西：

一页式结果看板
因果化特征
更严格的滚动验证 + 成本验证
这三件做好后，这套系统才会从“方法正确”变成“结果可信”。
