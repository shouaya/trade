# Rolling Feature PRD

## 文档定位

本 PRD 用于把当前 `train` 主链路下一阶段的业务优化目标写清楚，重点不是继续扩充基础设施，而是提升以下核心能力：

1. 让 rolling 过程中维护的候选池、市场特征、mapping 关系真正形成有效指导。
2. 让系统从“候选池里存在盈利策略”进一步走到“router 能更稳定地选中对的策略或及时停做”。
3. 让训练结果、rolling 决策、验证结果、目标达成率都可追踪、可解释、可持续迭代。

本 PRD 是 [train/METHODOLOGY.md](/Users/ts-changchang.zhuang/git/money/train/METHODOLOGY.md) 在下一阶段的细化执行版本，聚焦 BTCJPY 当前主链路，但结构要求应可复用于其他交易对。

## 一、背景与问题定义

### 1. 当前已经成立的事实

- 当前系统已经不是旧的“训练 2025，验证 2026”的固定切法，而是训练区间内部滚动验证。
- rolling 候选池会按月份更新，不是一次性生成后静态使用。
- 候选池中已经存在足够多的盈利策略，说明“策略家族完全无效”并不是主问题。
- 当前主问题已经收敛为：市场特征表达不够细，导致 router 对“该选谁、该减仓、该停做”的指导能力不足。

### 2. 第二轮暴露出的核心问题

结合现有 feature causality、goal tracking 与 rolling validation 结果，可以确认：

- 候选池里有赢家，但全体策略平均质量并不高，选择错误的代价很大。
- 当前特征更像“风险分层标签”，对精细选策略的表达力不够。
- 当前 rolling 规则主要还是按 `featureBucket` 聚合，数值特征虽然部分已支持，但还没有成为核心驱动。
- 市场特征、候选池变化、策略切换、失败反馈之间，尚未形成足够闭环的“滚动维护系统”。

### 3. 现阶段的业务判断

现阶段不应把重点继续放在手续费、命令行操作或旧兼容逻辑上，重点应放在：

- 市场特征是否足够刻画真实 regime；
- 特征是否真的驱动了 rolling 调整；
- router 是否能在月、周、日三个层级形成有效分工；
- 系统是否能稳定逼近“市场特征与策略库高度匹配，未来稳定盈利”的目标。

## 二、产品目标

### 1. 总目标

把当前 BTCJPY 训练主链路升级为一个真正由 rolling 特征驱动的策略维护系统，使其在训练期内部滚动验证中：

- 能持续维护候选池；
- 能持续维护特征与策略的 mapping；
- 能持续维护月线、周线、日线三个层级的决策；
- 能持续追踪目标达成率与失效来源；
- 为下一轮训练提供明确、可验证的改进方向。

### 2. 本阶段成功定义

本阶段成功不等于“立刻产出最高收益”，而是同时满足以下四点：

1. 新增特征能够解释当前弱月、弱周、弱日中的失效样本。
2. rolling 路由不再只依赖粗粒度 bucket，而是开始使用更细的数值条件与跨层状态。
3. router validation 可以稳定跑通并产出可比较结果。
4. 报告能明确说明：是候选池问题、特征问题、路由问题，还是风险控制问题。

### 3. 非目标

以下内容不属于本阶段主目标：

- 引入 ORM。
- 恢复旧脚本兼容逻辑。
- 做跨品种统一参数。
- 为实盘交易引入订单执行或交易所接入。

## 三、现状结论

### 1. 当前系统优势

- 候选池可按 rolling 方式维护。
- 月线、周线、日线、loss recheck 四层结构已经存在。
- 训练、验证、报告、goal tracking 已可自动串联。
- 数据已经能够通过 `train_id` 关联清理与追踪。

### 2. 当前系统短板

当前短板不是“没有特征”，而是“特征过粗且没有充分驱动决策”：

- 主要 bucket 仍由 `returnPct + realizedVolPct` 主导。
- `avgRangePct`、`upMinuteRatio` 等虽有计算，但对规则生成影响还不够强。
- 对趋势质量、波动扩张、开盘路径、反转强度、跨周期一致性、状态切换、候选池健康度的刻画不足。
- 当前系统更擅长回答“今天危险不危险”，还不够擅长回答“今天该选哪类策略”。

## 四、核心产品假设

### 假设 A：问题不在候选池是否存在机会，而在于 router 对机会的识别精度不足

如果这个假设成立，那么下一轮优化重点应放在：

- 提升特征表达；
- 提升规则生成方式；
- 提升 stop / reduce / strategy switch 的准确性。

### 假设 B：当前 opening / rolling 特征足以成为日级风险过滤器，但不足以成为高精度策略选择器

如果这个假设成立，那么下一轮需要补的不是单一“大杀器特征”，而是：

- 趋势质量特征；
- 波动结构特征；
- 日内路径特征；
- 跨层一致性特征；
- 候选池健康特征。

### 假设 C：rolling 的核心价值不只是“每月换 TopN”，而是“持续维护市场状态到策略动作的映射”

因此 rolling 必须维护的不只是候选池，还包括：

- 月级大环境；
- 周级基础策略；
- 日级切换 / 减仓 / 停做；
- 连续失败后的 recheck；
- 每次调整背后的因果解释与追踪指标。

## 五、范围

### 1. 本 PRD 覆盖范围

- BTCJPY 当前 1min 主链路。
- 训练期内部 rolling 验证机制。
- 月线 / 周线 / 日线 / loss recheck 的特征设计。
- 特征落库、规则生成、验证报告、目标追踪要求。

### 2. 本 PRD 不覆盖范围

- 跨品种联合训练。
- 非价格类外部因子。
- 实盘执行器。

## 六、训练与 rolling 的目标结构

### 1. 月线职责

月线负责定义：

- 当前月的大环境边界；
- 候选池应扩容、收缩还是防守；
- 哪些策略家族在该月优先保留；
- 是否需要降低整体风险上限。

月线不负责高频日内切换，但必须为周线和日线提供明确基调。

### 2. 周线职责

周线负责定义：

- 本周默认基础策略；
- 本周的风险上限；
- 周内是偏 continuation、reversal、range 还是 guarded balance；
- 当前周是否存在月线同方向确认，或出现月周冲突。

### 3. 日线职责

日线负责定义：

- 当日应 `trade`、`reduce` 还是 `stop`；
- 若可交易，应偏向哪一类具体策略；
- 当前日是趋势延续、冲高回落、震荡噪音还是高波动无 edge；
- 是否应该相对本周基调进行加速、减速或反向保护。

### 4. Loss Recheck 职责

loss recheck 负责定义：

- 前一日或连续数日失败后是否需要进一步保护；
- 当前失败是“正常波动”还是“当前 mapping 已失效”；
- 是否需要临时停做、切换到更保守策略，或降低风险倍数。

## 七、第三轮特征设计

### 1. 设计原则

所有新增特征必须同时满足以下原则：

1. 业务含义明确。
2. 计算可重复。
3. 尽量使用决策时点可见数据。
4. 能说明它将影响哪一层动作。
5. 能说明它想解决哪些失败样本。

### 2. P0 特征

#### 2.1 `trendEfficiency`

- 业务含义：价格净位移相对总路径长度的比例，用来区分“真趋势”与“高噪音伪趋势”。
- 主要作用层：周线、日线。
- 预期动作影响：
  - 高效率趋势：偏 continuation 或跟随型策略。
  - 低效率高波动：偏 reduce / stop 或 range 型策略。
- 目标问题：
  - 修复当前 `returnPct` 同方向但路径质量完全不同却被归为同类的问题。
  - 解释 `2025-11`、`2025-12` 这类盈利弱、但未必是极端崩坏的月份。
- 优先级：`P0`

#### 2.2 `volExpansionRatio`

- 业务含义：当前波动相对过去基线的扩张倍数，用来区分“正常波动”与“波动结构突变”。
- 主要作用层：月线、周线、日线。
- 预期动作影响：
  - 高扩张但无方向确认：减仓或停做。
  - 高扩张且方向效率高：允许使用更适合趋势爆发的策略。
- 目标问题：
  - 修复当前只看 realizedVolPct 而没区分“常规高波”与“异常扩张高波”的问题。
  - 重点覆盖 `2024-08` 以及 causality audit 里多个 opening 平静、全日爆发的错配日。
- 优先级：`P0`

#### 2.3 `openingImpulse`

- 业务含义：开盘后前 N 分钟的方向冲击强度。
- 主要作用层：日线。
- 预期动作影响：
  - 冲击强且延续条件成立：允许更快切换到趋势型策略。
  - 冲击弱或方向混乱：保守，必要时停做。
- 目标问题：
  - 让日级不再只靠整日 bucket 近似开盘状态。
  - 作为研究特征向 causal 特征迁移的核心入口。
- 优先级：`P0`

#### 2.4 `reversalStrength`

- 业务含义：开盘冲击之后反向吞没或回撤的强度。
- 主要作用层：日线、loss recheck。
- 预期动作影响：
  - 强反转：压制 continuation，偏向 reduce / stop / reversal 策略。
  - 弱反转：允许延续周线方向。
- 目标问题：
  - 区分“真突破”和“假突破后回归”。
  - 修复当前 bucket 对假突破识别不足的问题。
- 优先级：`P0`

#### 2.5 `positiveStrategyRatio`

- 业务含义：某 rolling 窗口下候选池中盈利策略占比。
- 主要作用层：月线、周线。
- 预期动作影响：
  - 占比高：说明当前结构下策略库整体适配，可放开。
  - 占比低：说明只有少数尖子生可用，应谨慎或减仓。
- 目标问题：
  - 把“候选池健康度”显式纳入决策，而不是只盯 best strategy。
- 优先级：`P0`

#### 2.6 `bestVsMedianGap`

- 业务含义：最佳策略与中位策略之间的收益差。
- 主要作用层：月线、周线、日线。
- 预期动作影响：
  - gap 很大：说明挑选错误成本高，router 必须更保守。
  - gap 适中且群体都赚钱：说明当前结构稳定，可更积极。
- 目标问题：
  - 解释“明明 best strategy 很赚，但系统整体不稳”的根源。
- 优先级：`P0`

#### 2.7 `monthlyWeeklyAlignment`

- 业务含义：月线基调与周线状态的一致程度。
- 主要作用层：周线。
- 预期动作影响：
  - 同向确认：允许维持或放大周线默认策略。
  - 冲突：优先减仓或只做防守型策略。
- 目标问题：
  - 解决周线孤立决策导致的误判。
- 优先级：`P0`

#### 2.8 `weeklyDailyAlignment`

- 业务含义：周线基调与当日状态的一致程度。
- 主要作用层：日线。
- 预期动作影响：
  - 一致：允许继续按周线基础策略执行。
  - 冲突：提高 `reduce` / `stop` 概率。
- 目标问题：
  - 把“周线定基调，日线做修正”真正写进决策，而不只是文档表述。
- 优先级：`P0`

### 3. P1 特征

#### 3.1 `closeLocationInRange`

- 业务含义：收盘位置在区间中的相对位置。
- 主要作用层：周线、日线。
- 价值：辅助判断趋势尾盘确认还是尾盘衰竭。
- 优先级：`P1`

#### 3.2 `wickImbalance`

- 业务含义：上下影线不对称程度。
- 主要作用层：日线。
- 价值：辅助识别逼空、冲高回落、抄底失败等微结构。
- 优先级：`P1`

#### 3.3 `rangeExpansionRatio`

- 业务含义：区间振幅相对历史基线的扩张比例。
- 主要作用层：周线、日线。
- 价值：补强 `volExpansionRatio`，更细分“波动大但未必有真实位移”的噪音结构。
- 优先级：`P1`

#### 3.4 `shockCount`

- 业务含义：日内极端波动段出现次数。
- 主要作用层：日线、loss recheck。
- 价值：识别当前日是否由事件冲击主导。
- 优先级：`P1`

#### 3.5 `morningVsAfternoonDrift`

- 业务含义：上午与下午方向一致性或偏离程度。
- 主要作用层：日线。
- 价值：区分“开盘定方向”与“盘中回转型”日。
- 优先级：`P1`

#### 3.6 `breakoutFollowThrough`

- 业务含义：突破后的延续质量。
- 主要作用层：日线。
- 价值：提高突破策略与反转策略的切换准确度。
- 优先级：`P1`

#### 3.7 `poolHealthScore`

- 业务含义：综合 `positiveStrategyRatio`、`bestVsMedianGap`、分散度等形成的候选池健康评分。
- 主要作用层：月线、周线。
- 价值：作为是否扩张候选池、是否偏保守的重要输入。
- 优先级：`P1`

### 4. P2 特征

#### 4.1 `bucketTransition`

- 业务含义：当前 bucket 相较上一周期是否发生结构跃迁。
- 主要作用层：周线、日线。
- 优先级：`P2`

#### 4.2 `trendPersistenceDays`

- 业务含义：同方向状态已经持续了多少天。
- 主要作用层：周线、日线、loss recheck。
- 优先级：`P2`

#### 4.3 `failedBreakoutRecentCount`

- 业务含义：近期失败突破出现次数。
- 主要作用层：日线、loss recheck。
- 优先级：`P2`

#### 4.4 `intradayDirectionEntropy`

- 业务含义：日内方向切换的混乱程度。
- 主要作用层：日线。
- 优先级：`P2`

## 八、特征如何作用于 rolling 决策

### 1. 月线

月线需要从“只描述 bucket”提升为“决定候选池与风险边界”：

- 用 `volExpansionRatio`、`positiveStrategyRatio`、`bestVsMedianGap`、`poolHealthScore` 决定本月候选池健康度。
- 用 `monthlyWeeklyAlignment` 决定是否允许周线策略偏激进。
- 当候选池健康差且月线结构恶化时，应优先产生 `reduce` 或 `stop-bias`，而不是继续维持正常风险。

### 2. 周线

周线需要从“按 bucket 选基础策略”提升为“按状态组合选基础策略”：

- `trendEfficiency + volExpansionRatio` 决定该周更像趋势周还是高波噪音周。
- `monthlyWeeklyAlignment` 决定周线是否接受月线方向背书。
- `positiveStrategyRatio + bestVsMedianGap` 决定这周默认应追求 alpha 还是先防守。

### 3. 日线

日线需要成为最强的执行修正层：

- `openingImpulse + reversalStrength` 负责最先判断当日是否适合趋势跟随。
- `weeklyDailyAlignment` 决定日线是否沿用周线基础策略。
- `breakoutFollowThrough`、`shockCount`、`morningVsAfternoonDrift` 决定是继续交易、减仓还是停做。

### 4. Loss Recheck

loss recheck 不能只是亏损后的机械补丁，而应显式结合：

- `reversalStrength`
- `shockCount`
- `failedBreakoutRecentCount`
- `trendPersistenceDays`

用来判断：

- 当前亏损是否代表当前 mapping 短期失效；
- 是否需要进入临时防守状态；
- 是否需要调低风险倍数而不是只停做一天。

## 九、数据与落库要求

### 1. 特征必须可追踪

下一轮开始后，新增特征不能只存在于内存或临时报表里，必须能追踪：

- 某次 train 的月线 / 周线 / 日线特征值；
- 某条规则实际引用了哪些特征；
- 某次 `trade / reduce / stop` 决策背后命中了哪些条件；
- 某个失败窗口是否与特征误判有关。

### 2. 规则必须可解释

rolling 过程中维护的 router / policy 不应再依赖手工文件作为系统主源，而应做到：

- 主数据在 DB；
- 文件只作为导出结果或快照；
- 每次 rolling 调整都有版本、来源、条件、动作、命中统计。

### 3. 候选池维护必须显式记录

每个月 rolling 更新时，必须可追踪：

- 新增了哪些策略；
- 删除了哪些策略；
- 保留了哪些策略；
- 是因为市场特征变化，还是因为策略表现退化；
- 候选池健康度如何变化。

## 十、报告与观测要求

### 1. 必须新增的观测维度

下一轮报告中至少要固定输出：

- 每月候选池健康度
- 每层 router 命中率
- `trade / reduce / stop` 占比
- 周线策略切换频率
- 日线相对周线的偏离率
- 失败月份的特征偏差说明
- 目标达成率变化

### 2. 必须能回答的问题

下一轮训练结束后，系统必须能直接回答：

1. 候选池有没有在 rolling 中变得更健康？
2. 哪些新增特征真正进入了规则，而不是只被计算出来？
3. 哪些弱月被修复了，哪些仍未修复？
4. router 的主要失误是误选、漏选还是该停没停？
5. 盈利是否仍然只集中在少数月份？

## 十一、验收标准

### 1. 功能验收

- rolling 训练后，月线 / 周线 / 日线特征可以被完整生成并追踪。
- 规则生成不再只依赖 `featureBucket` 单条件。
- router validation 能完整跑通并产出可比较结果。
- goal tracking 能反映 router 改进，而不是长期停留在空白或零分状态。

### 2. 业务验收

下一轮不要求立刻达到最终稳定盈利，但至少应满足：

- 新增特征确实进入规则。
- 至少一部分弱月的解释能力提升。
- `trade / reduce / stop` 更符合市场状态，而不是机械平均分布。
- 系统能更清楚地区分“机会多但难选”与“本身就不该做”的月份。

### 3. 失败判定

如果出现以下情况，应判定本阶段未达标：

- 特征数量增加，但规则仍几乎只按粗 bucket 工作。
- 候选池健康度没有进入任何决策层。
- router validation 仍无法形成稳定的比较结果。
- 报告仍无法解释弱月为什么弱、是否有改善。

## 十三、下一步执行建议

本 PRD 确认后，建议按以下顺序推进：

1. 先扩展特征定义与特征审计，不急着直接开第三轮训练。
2. 再升级 rolling rule 生成逻辑，让新增特征真正参与决策。
3. 然后补强报告和观测项，确保下一轮结果能解释清楚。
4. 最后再进行第三轮训练与 router validation，对照本 PRD 验收。

## 十四、结论

第三轮的重点，不是“再训一次看看运气”，而是把 rolling 系统真正升级为：

- 候选池会随市场结构调整；
- 市场特征会真实驱动策略选择；
- 月、周、日三层各司其职；
- 报告能说明系统到底离“未来稳定盈利”还有多远。

如果这一步做扎实，下一轮训练才有业务意义。
